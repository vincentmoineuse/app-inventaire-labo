# Guide de configuration et de déploiement

Ce guide t'accompagne pas à pas pour :
1. créer un projet Supabase (base de données + stockage des photos),
2. créer les tables et le bucket de photos,
3. mettre le code sur GitHub,
4. déployer l'application sur Streamlit Community Cloud (gratuit, accessible sur mobile).

Compte à rebours : ~10-15 minutes la première fois, uniquement à faire une seule fois.

---

## 1. Créer un projet Supabase

1. Va sur [supabase.com](https://supabase.com) et crée un compte (inscription par email ou
   via GitHub).
2. Clique **New project**, choisis une organisation (créée automatiquement si c'est ta première
   fois), donne un nom au projet (ex : `inventaire-labo`), choisis un mot de passe de base de
   données (peu importe, on ne s'en servira pas directement) et une région proche de toi
   (ex : Europe).
3. Attends une minute ou deux que le projet soit prêt.

## 2. Récupérer l'URL et la clé d'API

1. Dans le projet, va dans **Project Settings** (icône ⚙️ en bas à gauche) → **API**.
2. Note deux valeurs :
   - **Project URL** (ressemble à `https://xxxxxxxxxxxx.supabase.co`)
   - **service_role** (dans "Project API keys" — clique sur "Reveal" pour l'afficher). C'est
     une longue chaîne commençant par `eyJ...`.

⚠️ La clé `service_role` donne un accès complet à la base de données : elle ne doit **jamais**
être partagée publiquement ni placée dans du code visible côté navigateur. Elle restera
uniquement dans les *Secrets* Streamlit (côté serveur), ce qui est sûr.

## 3. Créer les tables

1. Dans le menu de gauche, va dans **SQL Editor** → **New query**.
2. Colle le script SQL ci-dessous, puis clique **Run**.

```sql
create table if not exists articles (
  id bigint generated by default as identity primary key,
  nom text not null,
  categorie text not null,
  quantite numeric(10,3) not null default 0,
  unite text default 'unité(s)',
  salle text,
  armoire text,
  photo_path text,
  numero_cas text,
  pictogrammes text,
  date_peremption date,
  notes text,
  date_ajout timestamptz not null default now(),
  date_dernier_inventaire timestamptz,
  actif boolean not null default true
);

create table if not exists sessions_inventaire (
  id bigint generated by default as identity primary key,
  date_debut timestamptz not null default now(),
  date_fin timestamptz,
  notes text
);

create table if not exists pointages (
  id bigint generated by default as identity primary key,
  session_id bigint references sessions_inventaire(id) on delete cascade,
  article_id bigint references articles(id) on delete cascade,
  quantite_avant numeric(10,3),
  quantite_apres numeric(10,3),
  date_pointage timestamptz not null default now()
);

-- Depuis fin avril 2026, Supabase n'expose plus automatiquement les nouvelles
-- tables à l'API (Data API / PostgREST), même pour service_role. Ces GRANT
-- rendent les tables accessibles à l'application.
grant usage on schema public to anon, authenticated, service_role;
grant all on all tables in schema public to anon, authenticated, service_role;
grant all on all sequences in schema public to anon, authenticated, service_role;

notify pgrst, 'reload schema';
```

Tu peux vérifier que les 3 tables sont bien créées dans **Table Editor** (menu de gauche).

⚠️ **Si tu as déjà exécuté ce script sans les `GRANT`** (par exemple en suivant une version précédente de ce guide), il suffit de réexécuter uniquement le bloc `grant ...` et `notify pgrst, 'reload schema';` ci-dessus dans une nouvelle requête SQL — les instructions `create table if not exists` ne recréeront rien puisque les tables existent déjà.

## 4. Créer le bucket de stockage des photos

1. Dans le menu de gauche, va dans **Storage** → **New bucket**.
2. Nomme-le exactement `photos` (en minuscules).
3. Active l'option **Public bucket** (pour que les photos s'affichent directement dans
   l'application sans configuration supplémentaire).
4. Clique **Create bucket**.

## 5. FDS et notices (PDF)

Si tu ajoutes cette fonctionnalité à une installation déjà existante, deux choses à faire en
plus (sinon, si c'est ta toute première installation, fais-les simplement à la suite des
étapes précédentes) :

**a) Ajouter les colonnes nécessaires** — dans **SQL Editor**, exécute :

```sql
alter table articles add column if not exists fds_path text;
alter table articles add column if not exists notice_path text;
notify pgrst, 'reload schema';
```

**b) Créer un second bucket de stockage, pour les PDF** — comme à l'étape 4, dans **Storage**
→ **New bucket**, nomme-le exactement `documents`, coche **Public bucket**, puis
**Create bucket**.

Tu peux ensuite attacher les FDS et notices depuis la page **📄 Documents** de l'application
(ou directement en ajoutant/modifiant un article) — y compris pour importer les PDF que tu
as déjà sur ton ordinateur.

## 6. Mettre le code sur GitHub

1. Crée un nouveau dépôt GitHub (public ou privé, les deux fonctionnent avec Streamlit Cloud).
2. Pousse tous les fichiers de ce projet **sauf** `.streamlit/secrets.toml` (qui n'existe pas
   encore de toute façon — seul `secrets.toml.example` doit être versionné, c'est prévu par le
   `.gitignore`).

```bash
git init
git add .
git commit -m "Application inventaire labo"
git branch -M main
git remote add origin https://github.com/TON-COMPTE/inventaire-labo.git
git push -u origin main
```

## 7. Déployer sur Streamlit Community Cloud

1. Va sur [share.streamlit.io](https://share.streamlit.io) et connecte-toi avec ton compte
   GitHub.
2. Clique **Create app** → **Deploy a public app from GitHub**.
3. Sélectionne ton dépôt, la branche `main`, et le fichier principal `app.py`.
4. Avant ou après le premier déploiement, va dans **⚙️ Settings** → **Secrets** de l'appli et
   colle-y le contenu de `.streamlit/secrets.toml.example`, en remplaçant :
   - `supabase_url` par la Project URL récupérée à l'étape 2,
   - `supabase_key` par la clé `service_role` récupérée à l'étape 2.
5. Sauvegarde. L'application redémarre et devient accessible via une URL du type
   `https://ton-appli.streamlit.app` — utilisable depuis n'importe quel navigateur,
   y compris sur smartphone (tu peux l'ajouter à l'écran d'accueil comme un raccourci).

## 8. Mises à jour futures

Toute modification poussée sur la branche `main` de GitHub redéploie automatiquement
l'application sur Streamlit Cloud en quelques dizaines de secondes.

## Dépannage

- **"Configuration Supabase incomplète"** → vérifie que les *Secrets* sont bien renseignés
  (étape 6.4) et qu'il n'y a pas de faute de frappe/espace dans l'URL ou la clé.
- **"Impossible d'accéder à la table 'articles'"** (avec un code `PGRST125` ou une erreur de
  permission) → depuis fin avril 2026, Supabase n'expose plus automatiquement les nouvelles
  tables à l'API. Va dans **SQL Editor** et exécute les instructions `grant ...` et
  `notify pgrst, 'reload schema';` données à l'étape 3 (tu peux les réexécuter seules si les
  tables existent déjà).
- **Les photos ne s'affichent pas** → vérifie que le bucket s'appelle exactement `photos` et
  qu'il est bien marqué **Public** (Storage → clique sur le bucket → icône ⚙️ → "Make public"
  si besoin).
- **Erreur liée à la clé Supabase** → assure-toi d'avoir copié la clé `service_role` (et non
  `anon`), qui a les droits nécessaires pour lire/écrire sans configuration supplémentaire.


## 6. Rubriques TP et Commandes

Si tu ajoutes ces rubriques à une installation existante, exécute ce script dans **SQL Editor** :

```sql
create table if not exists tps (
  id bigint generated by default as identity primary key,
  titre text not null,
  discipline text,
  niveau text,
  date_prevue date,
  notes text,
  date_ajout timestamptz not null default now(),
  actif boolean not null default true
);

create table if not exists tp_materiel (
  id bigint generated by default as identity primary key,
  tp_id bigint not null references tps(id) on delete cascade,
  article_id bigint references articles(id) on delete set null,
  libelle text,
  quantite numeric(10,3) not null default 1,
  unite text
);

create table if not exists commandes (
  id bigint generated by default as identity primary key,
  titre text not null,
  fournisseur text,
  statut text not null default 'À commander',
  date_commande date,
  date_livraison_prevue date,
  notes text,
  date_ajout timestamptz not null default now(),
  actif boolean not null default true
);

create table if not exists commande_lignes (
  id bigint generated by default as identity primary key,
  commande_id bigint not null references commandes(id) on delete cascade,
  article_id bigint references articles(id) on delete set null,
  designation text not null,
  reference_fournisseur text,
  quantite numeric(10,3) not null default 1,
  unite text,
  prix_unitaire numeric(10,2),
  recu boolean not null default false
);

alter table tps enable row level security;
alter table tp_materiel enable row level security;
alter table commandes enable row level security;
alter table commande_lignes enable row level security;

grant usage on schema public to anon, authenticated, service_role;
grant all on all tables in schema public to anon, authenticated, service_role;
grant all on all sequences in schema public to anon, authenticated, service_role;
notify pgrst, 'reload schema';
```


## 7. Accès administrateur et accès en consultation

L'application propose deux accès :

- **Administrateur** (toi) : mot de passe, accès à toutes les pages et à toutes les modifications.
- **Consultation** (personnes extérieures) : lecture seule de l'inventaire, des commandes (sans les prix),
  des fiches FDS, des documents et des TP. Ces visiteurs ne voient pas les pages d'ajout, de session
  d'inventaire ni d'export, et aucune modification n'est possible, même en cherchant à contourner l'interface.

À ajouter dans **Streamlit Cloud → ton app → Settings → Secrets** (à la suite de supabase_url et supabase_key) :

```toml
mot_de_passe_admin = "choisis-un-mot-de-passe-long"
code_consultation = "code-a-donner-aux-visiteurs"   # facultatif
```

- `mot_de_passe_admin` est **obligatoire** : sans lui, personne ne peut se connecter en administrateur.
- `code_consultation` est facultatif. S'il est absent, toute personne qui connaît le lien peut entrer en
  consultation d'un clic. S'il est présent, les visiteurs doivent saisir ce code.
- Après 5 tentatives incorrectes, l'écran de connexion se verrouille jusqu'au rechargement de la page.
- Le fait de recharger la page ou de laisser le téléphone se mettre en veille peut déconnecter : il suffit de se reconnecter.
